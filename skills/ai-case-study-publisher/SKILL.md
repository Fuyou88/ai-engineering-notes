# AI Case Study Publisher

把一次真实 AI 工程实践沉淀成可复用的个人技术博客，而不是会话摘要或流水账。

## 调用语义

- `$ai-case-study-publisher 草拟本次案例`：只生成或修改文章草稿，不提交、不推送。
- `$ai-case-study-publisher 发布本次案例`：授权写入目标仓库、更新索引、提交并推送。
- 未明确出现“发布 / 提交 / 推送”时，按草拟处理；不得把 Skill 点名本身解释为远端写入授权。

默认目标仓库：`https://github.com/Fuyou88/ai-engineering-notes`，文章目录为 `articles/`。

## 输入

优先使用用户指定的会话、任务、文档、代码或证据。未指定时，以当前会话为案例边界；材料不足以还原关键决策时，先报告证据缺口，不补写虚构过程。

## SOP

1. 读取 [references/workflow.md](references/workflow.md)，完成价值准入、事实还原、公开化和写作。
2. 依据案例主命题，从 [references/article-blueprints.md](references/article-blueprints.md) 选择一种最小文章结构；不要机械拼齐所有章节。
3. 草拟模式：输出文章文件和发布前检查结果，到此停止。
4. 发布模式：读取 [references/publish-contract.md](references/publish-contract.md)，完成仓库检查、索引、显式路径提交、推送和远端回读。

## 不变量

- 原汁原味保留问题、失败、质疑、转折和决策边界；压缩重复，不美化成事后正确。
- 每个关键断言绑定会话原文、代码、文档、命令输出或平台事实；推论明确标记为推论。
- 公开文章不包含凭据、个人本机路径、内部链接、未授权身份信息或可识别的业务敏感细节。
- 匿名化只移除识别信息，不改变因果链、技术约束和结论。
- 文章必须回答“为什么值得复用”以及“结论在哪些条件下不成立”。
- 不为统一模板制造虚假的数据、时间线、对比结果或验证结论。

## 完成标准

草拟完成：文章可独立阅读，价值、证据、适用边界和未验证项齐全，隐私检查通过。

发布完成：文章与 README 索引位于远端默认分支；提交只包含本次文章及必要索引；远端回读确认文章 URL 和提交 SHA。
