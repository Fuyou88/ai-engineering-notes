# 文章蓝图

蓝图用于选择叙事重心，不是强制模板。一个案例只选一个主蓝图，必要时借用其他蓝图的一两个章节。

## A. 事故 / 失败复盘

适合：一次改造、Agent 执行或治理机制出现明显退化。

推荐主线：

```text
原目标与基线
→ 表面症状
→ 连锁失败
→ 为什么局部修补无效
→ 共同根因
→ 修复与验证
→ 防复发检查表
```

必须保留：旧方案或失败改造为什么在当时看起来合理。

## B. 架构 / 设计哲学

适合：案例最终形成两套或多套成立条件不同的设计选择。

推荐主线：

```text
问题背景
→ 旧模型及其正当性
→ 失效条件
→ 新模型的不变量
→ 两套哲学对照
→ 各自适用边界
→ 迁移路径
```

必须保留：反例和“不该采用新方案”的条件，避免口号化。

## C. 方法 / SOP 演进

适合：从一次实践中抽象出稳定的工作流、Skill 或工具组合。

推荐主线：

```text
真实场景
→ 初始做法
→ 重复成本或失败
→ 方法抽象
→ SOP / 产物门禁
→ 示例
→ 适用范围与维护方式
```

必须保留：方法解决的具体失败，以及何时不值得工程化。

## D. 方案对比 / 决策记录

适合：多个可行方案需要证据化裁决。

推荐主线：

```text
决策问题
→ 约束与评价维度
→ 方案 A / B / C
→ 证据与反证
→ 决策及放弃项
→ 回看条件
```

必须保留：未验证项、决策可逆性和未来重新评估的触发条件。

## 标题判据

标题优先表达“张力 + 结论”，例如：

- 为什么越加 Guardrail，系统反而越不稳定
- 事实优先于流程：为什么我们删除了全局 Coordinator
- 从一次视觉还原复盘到可执行 Skill

避免“某某总结”“一些思考”“最佳实践”等不能约束正文的标题。
