# GitHub 发布合同

## 授权边界

只有用户在本次调用中明确要求“发布、提交或推送”时，才允许产生 GitHub 远端写入。草拟、整理、沉淀、写文章本身只授权本地草稿。

## 仓库与范围

默认仓库：`Fuyou88/ai-engineering-notes`

默认变更范围：

- 新增或修改一个 `articles/*.md`；
- 更新 `README.md` 的 Articles 索引；
- 用户明确要求时，才修改其他文件。

若用户提供现有 checkout，先读取仓库指令和工作树状态，保留无关改动。未提供时使用临时目录克隆默认分支，避免污染其他工作区。

## 发布步骤

1. 确认 GitHub 身份对目标仓库有写权限，并读取默认分支。
2. 拉取最新默认分支；检查 `AGENTS.md`、README、最近文章和提交消息惯例。
3. 生成文章并更新 README 索引；链接使用仓库相对路径，空格编码为 `%20`。
4. 检查 `git diff --check`、代码围栏成对、README 目标存在、敏感信息扫描和变更范围。
5. 只暂存文章与 README 的显式路径，检查 staged diff 和 stat。
6. 使用描述发布结果的提交标题，不伪造 issue、co-author 或测试结论。
7. 推送前再次确认本地基线未落后于远端；发生并发更新时安全整合后重新检查。
8. 推送默认分支；远端回读提交 SHA、文章对象和 README 索引。

## 停止条件

出现以下任一情况时停止发布并报告：

- 写权限、身份或目标仓库不确定；
- 远端出现无法安全整合的并发更新；
- 仓库存在与本次范围交叉的用户改动；
- 文章仍包含敏感信息或无证据的关键断言；
- 用户只授权草拟。

## 交付回报

返回：文章标题与 GitHub URL、提交 SHA 与主题、修改范围、实际执行的检查，以及任何未发布或未验证项。
